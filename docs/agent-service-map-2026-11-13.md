# Agent service and gap map

Research date: 2026-11-13. Scope: University of Tübingen and the surrounding services that affect student life, including international arrivals. This is a prioritized inventory, not an exhaustive list of every faculty system. Repository observations describe code present, not live production guarantees. No authenticated systems were tested.

## How to read the map

- **Implemented**: a client, parser or route exists in this checkout. Coverage can be narrower than the upstream service.
- **Exposure gap**: implementation exists, but the local `tue-mcp` server does not expose the relevant feature. The ChatGPT app is a separate MCP surface and must be assessed separately.
- **Missing**: no dedicated integration was found during this source review. **Unknown**: feasibility, account access, or actual coverage needs investigation. Absence of a repository search hit is not proof that no code exists anywhere.
- **Public**, **private**, and **write** refer to upstream access. A public page is not evidence of a public API. A write may have financial, academic, or legal effects.

## Prioritized work packages

Ranking is an engineering judgment about user impact, frequency, feasibility and consequence of failure; it is not a measured score or an implementation promise. Every package begins with a source and contract audit.

| Order | Package | Build / investigation | Completion check |
| --- | --- | --- | --- |
| 0 | Safe agent access | Document install, local credentials, service selection and network prerequisites; audit local HTTP/MCP authorization and CLI contracts. | A fresh agent can discover public tools and distinguish auth, network and permission failures; no secrets in output. |
| 1 | Cross-system deadlines and changes | Expose existing ILIAS assignment/quiz, Moodle deadlines, timetable and Alma notices; add source-aware snapshots and per-source outcomes. | A 7-day view reports exact source, timestamp, status, truncation and failed sources; rerun identifies changes without declaring failed sources empty. |
| 2 | Course materials and feedback | Audit course trees, nested ILIAS folders, supported Moodle activities, file content, submissions and feedback; expose verified read operations. | Two different authorized courses can be browsed with clear coverage and accessible materials linked to their sources. |
| 3 | Exam and study administration | Expose exam/enrollment/study planner inspection; investigate Alma payment tab and exam registration periods. | Agent distinguishes enrolled course, platform membership, registered exam and actual payment state. Missing or uncertain states remain unknown. |
| 4 | Library | Inspect Katalog plus, implement catalogue and read-only account if feasible; plan renewal/hold separately. | Search returns source-linked availability; own loans show due dates and account errors without claiming unsupported renewal. |
| 5 | International arrival and city | Index current official sources for housing, registration, residence permits, health insurance and contacts; route by municipality and circumstances. | Given an example profile, return sourced steps and unresolved questions; do not fabricate appointment availability, deadlines or application status. |
| 6 | Programme rules | Index examination-office/faculty regulations and handbooks with programme, version, effective dates and provenance. | An answer cites the correct programme version and exposes uncertainty; recognition and exam access remain official decisions. |
| 7 | Notices and communications | Expose existing Alma notices, Moodle notifications and limited mail search/detail; investigate ILIAS announcement and forum detail. | A daily digest links to source and reports missing access, without bulk mailbox ingestion. |
| 8 | Daily campus logistics | Expose existing food, locations, seats, sport, anny resource search through agent interfaces; add verified opening-hours coverage. | Agent can answer food or space queries with current data and limitations; booking remains distinct from availability. |
| 9 | Actions and additional systems | Assess safe preview, explicit confirmation, authorization and post-action verification for registration, renewal, reservation and submission. Expand to printing, funding and transport after access discovery. | Each supported action previews an exact target and side effects, binds approval to the payload, and reports verified outcome or uncertainty. |

These packages can be reprioritized by user research. Work on library and international arrivals can proceed independently of learning-platform work.

## Cross-cutting constraints and open questions

- **Network:** The [ZDV Alma page](https://uni-tuebingen.de/einrichtungen/zentrum-fuer-datenverarbeitung/dienstleistungen/server/alma-portal/) describes university-network/eduVPN access. Verify current connectivity for each service and environment; do not assume cloud agents can reach them.
- **Credentials and exposure:** [Authentication boundaries](authentication-boundaries.md) describe current local-only design and HTTP risks. Private results sent to a remote agent or model leave the local trust boundary even when passwords remain local. A persistent cloud deployment needs a separate design and explicit user choice.
- **Correctness:** Store upstream identifiers, observation time, source URL, original dates and timezone, filters, pagination and completeness. Never convert an unknown date or failed source into an empty list or confirmed deadline.
- **Untrusted content:** Course pages, files and messages may contain instructions. Treat their content as data, not authority to invoke tools or disclose private information.
- **Privacy and side effects:** Restrict data to the selected workflow, minimize retention and avoid logs of private content. Preview state-changing actions and respect the current skill and surface confirmation policies.
- **International applicability:** Sources can vary by nationality, visa, residence, programme and date. Cite the relevant official page and direct unresolved cases to the responsible authority. Do not encode examples as universal legal rules.
- **Validation still needed:** Live account testing, operator/API terms, rate limits, current service reachability, course and faculty diversity, accessibility, and testing of the Go CLI across supported platforms were outside this research.
